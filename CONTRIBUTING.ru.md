# Участие в разработке STEALTHNET

Начните с [руководства разработчика](docs/ru/development.md), [разделов панели](docs/ru/README.md) и [LICENSE](LICENSE). Вносите только изменения, которые вправе предоставлять на условиях лицензии проекта. Не копируйте чужой код, изображения и документацию без проверки лицензии и сохранения необходимых уведомлений. Изучение протокола и сравнение поведения продуктов не равнозначны копированию реализации.

## До изменения

Опишите конкретную проблему и ожидаемый результат. Перед крупным изменением обсудите совместимость данных, миграции и пользовательский сценарий. Клиентские возможности должны настраиваться из админки там, где это предусмотрено продуктом. Не подставляйте демонстрационных клиентов, платёжные ключи и выдуманные показатели в рабочие данные.

## Подготовка изменений

- Ограничьте изменение решаемой задачей и объясните поведение до/после.
- Добавляйте новую миграцию вместо редактирования выпущенной.
- Сохраняйте настройки владельцев и совместимость обновления.
- Обновляйте RU/EN подписи, подсказки, справку и парные страницы документации.
- Проверяйте телефон/ПК и обе темы при изменении интерфейса.
- Воспроизводите реальную границу ошибки; не отправляйте тестовые оплаты и сообщения клиентам.

Проверки по характеру изменения:

```bash
make test-release
python3 devtools/check-docs.py
cargo test --locked --workspace --lib --bins
```

Укажите, что проверено, а что нет. Изменения установки требуют проверки в VM с настоящими systemd/PostgreSQL; платёжные изменения — подписей, дублей и порядка callback в изолированном окружении.

## Pull request

Опишите проблему, новое поведение, проверки и действия владельца при обновлении. Для UI приложите обезличенные скриншоты. Не включайте .env, клиентские данные, внутренние аудиты, коды, платёжные ключи и локальные сборки. Для уязвимостей действует [SECURITY.md](SECURITY.md).

Публикация в GitHub и первый стабильный релиз ещё предстоят. Локальная подготовка не означает, что изменения уже доступны в публичном репозитории.
