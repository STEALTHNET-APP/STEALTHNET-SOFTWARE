Установка кабинета и Mini App

Клиентский сайт и приложение Telegram обслуживает одна служба sn-cabinet. Панель хранит аккаунты и настройки. На клиентском сервере нет базы данных, токена бота и ключей платёжных систем.

Пустые обязательные поля уже содержат стартовые тексты RU/EN, SEO, цвета и стандартный логотип с домена вашей панели. Их можно изменить; ваши существующие значения сохраняются. Включите публикацию и нажмите «Сохранить настройки» перед запуском команды.

До установки

  1. Откройте Кабинет и Mini App → Брендинг и содержимое. Заполните название, логотип, favicon, цвета, тексты витрины и SEO. Включите нужные функции, сохраните настройки и опубликуйте кабинет.
  2. В Серверы и установка добавьте название, отдельный HTTPS-домен и IP сервера. Домен должен отличаться от доменов панели и подписки.
  3. Создайте DNS A на IP сервера. Если используете AAAA, IPv6 также должен вести на этот сервер. Откройте входящие TCP 80 и 443. Порт службы 8090 должен быть доступен только локально.
  4. На сервере нужны Debian/Ubuntu и systemd. Учётная запись SSH должна иметь права root.
  5. Нажмите Получить команду установки. В ней уже будут ваши домены и индивидуальный служебный ключ. Ключ отображается только один раз.

Пока кабинет не установлен, в админке показывается «Не установлен». Адрес Mini App не подставляется из панели. Старый адрес /app/ на домене панели показывает страницу недоступности.

На одном сервере с панелью

  1. При добавлении сервера выберите Сервер панели и его IP.
  2. Подключитесь по SSH к серверу панели и выполните команду из админки.
  3. Установщик проверит ключ и сборку, добавит sn-cabinet на 127.0.0.1:8090 и отдельный сайт в существующий Caddy. Домены панели и подписки сохраняются.
  4. Откройте домен кабинета. В админке статус должен измениться на На связи.

Автоматическое добавление HTTPS рассчитано на установку панели через install.sh со стандартным systemd-сервисом Caddy. Если reverse proxy работает в Docker или используется nginx, установщик остановится при конфликте портов. Настройте этот proxy самостоятельно, не останавливая панель.

На отдельном сервере

  1. Выберите Отдельный сервер, укажите его IP и направьте на него DNS клиентского домена.
  2. Войдите по SSH именно на этот сервер и выполните полученную команду.
  3. Установщик поставит службу и Caddy, запросит HTTPS-сертификат и проверит готовность сайта.
  4. Проверьте витрину и статус На связи в админке. Панель должна оставаться доступна по HTTPS с клиентского сервера.

В обоих вариантах ключ хранится в /etc/sn-cabinet/env с правами 600. Сервис читает только разрешённые клиентские маршруты панели. Отзыв ключа немедленно прекращает доступ сайта и Mini App к данным.

Существующий nginx или Caddy в Docker

Добавьте CABINET_PROXY=external после env в команде установки из админки. Будет установлена только служба кабинета; работающий reverse proxy не меняется. Направьте HTTPS-домен кабинета на 127.0.0.1:8090.

Блок для существующего системного Caddy:

cabinet.example.com {
    header Strict-Transport-Security "max-age=31536000"
    reverse_proxy 127.0.0.1:8090 {
        header_up X-Real-IP {remote_host}
    }
}

В nginx добавьте в отдельный HTTPS server с сертификатом клиентского домена:

add_header Strict-Transport-Security "max-age=31536000" always;
location / {
    proxy_pass http://127.0.0.1:8090;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

Для контейнера reverse proxy в Linux используйте сеть хоста: network_mode: host. Тогда loopback 8090 доступен контейнеру, а внешний порт службы остаётся закрыт. Проверьте конфигурацию до перезагрузки proxy, затем откройте /ready на HTTPS-домене кабинета.

Включение Mini App

  1. В разделе серверов выберите установленный кабинет в поле Кабинет для Mini App.
  2. В Телеграм-бот → Mini App включите приложение и сохраните настройки.
  3. Скопируйте показанный в админке адрес https://ваш-клиентский-домен/app/ в @BotFather, если используете главное Mini App или кнопку меню Telegram.
  4. В своём боте нажмите /start: кнопка откроет приложение с того же клиентского сервера.

Данные Telegram проверяются по подписи бота. Сайт использует код доступа и защищённую cookie-сессию. Mini App не использует cookie сайта: оба способа входа открывают один клиентский аккаунт после привязки.

Если не выбран кабинет, публикация отключена, ключ отозван или сервер не отвечает, Mini App недоступно. После потери связи кнопка исчезнет при следующем действии пользователя, когда истечёт двухминутное окно проверки. Настройки оформления применяются при обновлении экрана; бот читает новый адрес при следующем действии.

Обновление и смена ключа

При обновлении готовой установки до v0.2.5 и новее make update обновляет панель и стандартный кабинет на этом же сервере, подключённый к этой панели. Ключ и настройки сохраняются; при ошибке проверки возвращаются предыдущие бинарники. Отключённая и остановленная служба не включается автоматически.

cd /opt/stealthnet-software && make update

Для кабинета на другом сервере, нестандартного размещения или установки панели из исходников запустите на сервере кабинета:

sudo bash /usr/local/sbin/update-cabinet

Если обновляющий скрипт ещё не установлен, возьмите /update-cabinet.sh с домена своей панели, сохраните файл, просмотрите и запустите от root. Он читает адрес панели из файла настроек, проверяет SHA-256, сохраняет предыдущую сборку и откатывается при провале проверки готовности.

При выпуске нового ключа старый перестаёт работать сразу. Отредактируйте только значение CABINET_SERVICE_KEY в /etc/sn-cabinet/env, затем:

systemctl restart sn-cabinet
curl -fsS http://127.0.0.1:8090/ready

Восстановление отозванного ключа

Нажмите Восстановить ключ и команду в карточке сервера. Ключ можно восстановить и при выключенной публикации; перед запуском команды включите публикацию и сохраните настройки. Отзыв ключа снимает сервер с выбора для Mini App. Старая недоступная привязка больше не блокирует сохранение. После запуска кабинета выберите доступный сервер для Mini App заново.

Проверка и диагностика

HTTP 400 на шаге «Проверяем кабинет в панели»: если панель сообщает «Сайт ещё не опубликован», откройте Кабинет и Mini App → Брендинг и содержимое, заполните обязательные поля, включите Опубликовать кабинет и разрешить Mini App и нажмите Сохранить настройки. После успешного сохранения повторите ту же команду установки. Это относится и к установке на сервере панели. Новый ключ и переустановка панели не нужны. При HTTP 401/403 получите актуальную команду с ключом в разделе серверов.

systemctl status sn-cabinet --no-pager
journalctl -u sn-cabinet -n 50 --no-pager
curl -fsS http://127.0.0.1:8090/ready
systemctl status caddy --no-pager
journalctl -u caddy -n 50 --no-pager

Проверьте сайт на телефоне и ПК: витрину, регистрацию с сохранением кода, повторный вход и открытие Mini App. Реальную оплату проверяйте на настроенном тестовом способе оплаты; возврат из платёжной страницы сам по себе не подтверждает платёж.
