Customer site and Mini App installation

The website and Telegram Mini App use one sn-cabinet service. Accounts, billing and settings remain on the panel. The customer server does not need a database, a bot token or payment provider secrets.

1. Prepare the site

  1. Open Customer site and Mini App → Branding and content. Set the brand, logos, favicon, colors, Russian and English content, and SEO. Enable the required features, save and publish.
  2. Under Servers and installation, add a dedicated HTTPS domain and the server IP. Use a different domain from the panel and subscription service.
  3. Point its DNS A record to this server. Add AAAA only if IPv6 works on the same server. Allow inbound TCP 80 and 443. Keep port 8090 private.
  4. Use Debian or Ubuntu with systemd and root SSH access. Select Get installation command. Keep the service key in that command private.

2. Install on the panel server

Select Panel server and use its IP. Run the command over SSH on that server. The installer adds the customer service at 127.0.0.1:8090 and a separate site in Caddy. Existing panel and subscription domains are preserved. Open the customer domain and verify that its status becomes online.

3. Install on a separate server

Select Separate server, set its IP and point the customer domain there. Run the installation command on that server. It installs the service and Caddy, requests a TLS certificate and checks readiness. The customer server must be able to reach the panel over HTTPS.

The key is stored in /etc/sn-cabinet/env with permissions 600. Revoking it stops both the website and Mini App from accessing panel data.

Existing nginx or a proxy in Docker

Add CABINET_PROXY=external after env in the generated command. The installer then sets up the customer service without changing the proxy. Configure a dedicated HTTPS domain that forwards to 127.0.0.1:8090 and supplies the actual client IP.

cabinet.example.com {
    header Strict-Transport-Security "max-age=31536000"
    reverse_proxy 127.0.0.1:8090 {
        header_up X-Real-IP {remote_host}
    }
}

For nginx, use an HTTPS server block with the customer domain's certificate:

location / {
    proxy_pass http://127.0.0.1:8090;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

A Linux proxy container can use network_mode: host to reach the loopback service. Validate the proxy configuration before reloading it, then check the customer domain's /ready endpoint.

4. Enable the Mini App

  1. Select the installed server in Customer site for Mini App.
  2. Enable Mini App in the bot settings and save.
  3. Copy the customer site's /app/ URL to @BotFather when configuring the main Mini App or Telegram menu button.
  4. Send /start to your bot and open the Mini App.

The website authenticates with an access code and a secure cookie. The Mini App authenticates signed Telegram data. Linking the accounts makes both methods open the same subscription. Without a published, connected customer server, the Mini App is unavailable. The old panel /app/ address does not host the Mini App.

5. Update and rotate the server key

sudo bash /usr/local/sbin/update-cabinet

If the updater is missing, download /update-cabinet.sh from your panel, inspect it and run it as root. It verifies the binary checksum, preserves settings and restores the previous binary if readiness fails. Do not reinstall over an existing service.

A newly issued server key revokes the previous one. Update CABINET_SERVICE_KEY in /etc/sn-cabinet/env, then restart:

systemctl restart sn-cabinet
curl -fsS http://127.0.0.1:8090/ready

Diagnostics

systemctl status sn-cabinet --no-pager
journalctl -u sn-cabinet -n 50 --no-pager
curl -fsS http://127.0.0.1:8090/ready
journalctl -u caddy -n 50 --no-pager

A 503 readiness response means the panel or service authorization is unavailable. Check the panel URL, publication, server key and outbound HTTPS. If HTTPS fails, check DNS A/AAAA, inbound TCP 80/443, certificate issuance and proxy conflicts. Keep environment files and access codes out of public logs. A working website does not itself prove VPN connectivity: import a real subscription into a client and test the connection.
